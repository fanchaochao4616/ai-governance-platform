## D001 · 交付形态：FastAPI + 简单 Web UI

| 项 | 内容 |
|----|------|
| **日期** | 2026-07-18 |
| **状态** | 已采纳 |
| **决策** | MVP 采用 FastAPI REST + 原生 JS 单页 UI，不引入 React/Next 重构建链 |
| **备选** | CLI-only；Streamlit；仅 API+SDK |
| **理由** | 内部 pilot 需要可操作界面；工程化足够、启动快；OpenAPI 自文档利于联调 |
| **后果** | UI 以功能优先；复杂可视化后续可替换前端而不改服务层 |

## D002 · 存储：SQLite 单机

| 项 | 内容 |
|----|------|
| **日期** | 2026-07-18 |
| **状态** | 已采纳（MVP） |
| **决策** | 业务数据用 SQLite（SQLAlchemy）；上传/导出落本地 `data/` |
| **备选** | PostgreSQL；纯 JSONL 文件系统 |
| **理由** | 零运维、万级足够、与内部 pilot 匹配 |
| **后果** | 写并发弱；万级标注用批 commit + WAL；生产迁 PG 时主要改 `DATABASE_URL` |

## D003 · 导入导出格式：CSV + Excel（非 JSONL 主推）

| 项 | 内容 |

## D005 · 人工最终停止权（系统不自动跳轮）

| 项 | 内容 |
|----|------|
| **日期** | 2026-07-18 |
| **状态** | 已采纳（PRD 核心原则） |

## D020 · 判定阈值在全量标注之后设置

| 项 | 内容 |
|----|------|
| **日期** | 2026-07-18 |
| **状态** | 已采纳 |
| **决策** | 创建 Job **不设**判定阈值。流程：全量/本轮标注只产出 `confidence` → 状态 `AWAIT_DECISION_THRESHOLD` → 用户看分布后设阈值 → 批量映射 满足/不满足 → 再进入置信度分层 QC |
| **Gold** | 优化阶段用内部默认 `DEFAULT_DECISION_THRESHOLD`（0.5）仅算 Accuracy，不要求用户提前设阈值 |
| **API** | `POST /jobs/{id}/decision-threshold` body: `{threshold, round_no?}` |

## D017 · 不配置多分类标签：置信度阈值判定

| 项 | 内容 |
|----|------|
| **日期** | 2026-07-18 |
| **状态** | 已采纳 |
| **决策** | 用户**不设置**标签列表与标签说明。唯一业务输入是**风控细则** + **判定阈值** `decision_threshold`。模型输出 `confidence∈[0,1]`（文本满足细则的程度）；`confidence ≥ threshold` → **满足**，否则 **不满足** |
| **理由** | 业务侧以细则命中强度为准，避免维护多分类 taxonomy；与置信度筛选主流程一致 |
| **实现** | `app/services/labeling.py`；`AnnotatorAgent` 只打分；`JobCreate` 去掉 labels；UI 去掉标签/说明字段 |
| **Gold** | label 列仅 `满足`/`不满足`（兼容 是/否、1/0 等别名归一化） |
| **后果** | 原多分类 schema 模式废弃；旧 Job 若仍带自定义 labels 不影响已存数据，新建 Job 一律 confidence 模式 |
