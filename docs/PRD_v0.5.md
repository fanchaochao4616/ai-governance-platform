## 概述

### 背景

内容风控团队需要高质量单标签文本分类数据用于BERT训练和大模型微调。传统人工全量标注成本高、速度慢；纯大模型标注一致性差、政策对齐难。prompt工程缺乏系统沉淀，且多轮标注结果难以追踪与聚合。

### 问题陈述

现有工具无法支持“人工每轮主导决策 + 动态置信度筛选 + 多轮结果智能聚合”的低成本高质量标注流程，导致数据生产效率低、知识无法复用。

### 产品目标

打造以人工决策为核心的AI辅助标注平台，通过质检大模型 + 标注小模型 + 动态gold test set迭代优化 + 人工每轮定义置信度范围与决策 + 永久序号追踪多轮标注 + Prompt知识库，在保障内容风控质量的前提下显著降低标注成本，并将prompt经验固化为团队资产。

### 成功指标（North Star + KR）

**North Star**：单Job产出可直接用于BERT训练的高质量标注数据，人工干预量降低70%+，同时形成可复用的Prompt知识资产。

**模型性能KR**（参考指标，非硬性通过条件）：

- Gold test set最终Accuracy达到用户设定阈值（支持设置为100%）
- QC样本human agreement（人工gold）作为重要参考
- Badcase rate持续下降
- Test set随Job增长，prompt优化收敛速度提升

**业务KR**：

- 多轮标注中，通过人工指定置信度范围筛选，显著降低需重标样本量
- Prompt模板复用率 > 40%
- 人工每轮决策后能快速生成有效prompt改进建议

## 用户与场景

### 目标用户画像

内容风控中台AI工程师、数据工程师、质检负责人（内部团队优先）。

### 核心用户故事

1. 作为风控工程师，我想上传万级数据 + 初始gold test set，配置任务后，系统在gold test set上迭代优化prompt直至达标，再用小模型完成首轮全量标注。
2. 作为质检负责人，每一轮小模型标注完成后，我可以自定义置信度分层范围，系统按我的范围抽取QC样本，我审查后决定是否继续下一轮、给出feedback，并指定下一轮要处理的置信度范围。
3. 作为数据工程师，我想通过永久序号查看单条数据的所有多轮标注历史，并选择取哪几轮结果进行平均作为最终label。

### 边缘Case与失败处理

- 边界模糊、政策更新导致的持续badcase → 通过人工每轮feedback持续优化prompt
- 人工判断质量已达标 → 可随时手动停止后续轮次

## 功能需求

### MVP范围

仅支持单标签文本分类（内容风控场景），数据规模万级，内部团队使用。核心能力包括人工每轮决策、动态置信度分层抽样、永久序号多轮追踪、prompt改进建议生成、调试记录与模板库。

### P0 核心功能（必须MVP上线）

#### 1. 数据集与任务配置

- 上传全量未标注数据 + 初始gold test set
- 定义单标签schema + 风控细则
- 配置目标阈值（支持100%）、最大迭代次数、token预算上限

#### 2. 双Agent标注作业（Gold Test Set优化）

- 质检大模型负责prompt设计、badcase分析与迭代优化
- 标注小模型在gold test set上验证
- 直至达到用户设定阈值后进入全量标注

#### 3. 全量标注与多轮置信度筛选机制

- 首轮：小模型对全量数据标注，系统自动为每条数据分配永久不变的序号（作为主键）
- 每轮标注完成后：
  - 用户自定义置信度分层范围（High / Medium / Low）
  - 系统按用户定义范围分层抽取QC样本
  - 人工审查、纠正、填写反馈
  - 人工决策：是否继续下一轮、feedback内容、下一轮处理的置信度范围
- 系统只对人工指定的置信度范围样本进行下一轮重标，并增加新轮次记录（序号不变）
- 支持用户选择取几到几轮标注结果进行平均作为最终label

#### 4. 人工质检与动态Gold Test Set

- 每轮必须人工参与质检
- 纠正样本自动并入gold test set
- 质检大模型根据人工feedback自动生成prompt改进建议

#### 5. Prompt调试记录

- 每个Job完整记录prompt演化时间线（每版本prompt、test set指标、badcase、变更驱动因素、关联QC反馈、token消耗）
- 支持版本diff、回滚、导出调试报告

#### 6. 优质Prompt模板知识库

- 自动推荐 + 手动保存优质prompt为模板
- 支持分类、效果评分、搜索复用
- 新建Job可从历史优质模板启动

#### 7. 基础监控与导出

- 实时成本、质量指标、test set增长、多轮筛选统计
- 导出带最终label + 多轮历史 + 永久序号的结果文件

## 非功能需求

- **成本控制**：每Job提供预估 + 硬预算上限；人工每轮指定置信度范围可显著降低重标成本
- **性能**：支持万级数据多轮处理
- **安全**：数据加密、审计日志、序号对模型不可见
- **可靠性**：结构化输出强制、冲突提示

## AI特定规格

### 模型选型

- 质检大模型：Grok 4.5/4.20（high reasoning）—— prompt优化、badcase分析、生成改进建议
- 标注小模型：Grok 4.1 Fast variant —— 各轮标注主力

### Prompt策略

- 角色 + 风控细则 + CoT + 结构化JSON输出（label, confidence, reasoning）
- 支持动态few-shot

### 评估框架

- Gold test set（初始 + QC增长），目标支持用户设为100%
- 参考指标：Accuracy、Macro-F1、badcase分类、QC human agreement
- 多轮标注统计：平均轮次、筛选跳过效果

### Guardrails

- JSON schema强制 + confidence阈值
- 多轮冲突自动提示
- 序号对模型隐藏

### 数据飞轮设计

人工每轮feedback + 指定置信度范围 → 丰富gold test set与prompt模板 → 后续Job成本更低、收敛更快

## 信息架构与流程

### 核心实体

Job、Dataset、GoldTestSet（动态增长）、AnnotationRecord（永久序号 + 多轮历史）、PromptVersion、PromptTemplate、QCFeedback

### 主流程（每轮状态机）

1. 小模型完成当前轮标注（分配/使用永久序号，输出confidence）
2. 用户自定义置信度分层范围（High/Medium/Low）
3. 系统按用户范围分层抽取QC样本
4. 人工审查 + 纠正 + 填写反馈
5. 人工决策三项内容：
   - 是否继续下一轮
   - feedback内容（给质检大模型）
   - 下一轮处理的置信度范围
6. 系统执行：生成prompt改进建议 + 只对指定范围样本重标 + 记录新轮次
7. 当人工选择“不需要继续下一轮”时，流程结束，以多轮平均结果作为最终输出。

## 风险与假设

### 主要风险与缓解

- 人工每轮决策负担重 → 提供清晰指标摘要 + prompt改进建议辅助 + 默认推荐
- 置信度范围定义不合理 → 支持实时查看当前轮置信度分布后再定义
- 多轮结果管理复杂 → 以永久序号作为主键进行清晰聚合

### 核心假设

- 用户能提供高质量初始gold test set
- 人工每轮参与可接受，且能通过反馈有效驱动prompt改进
- 置信度与实际标注质量存在较强相关性
